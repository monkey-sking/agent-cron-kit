# 共享审核：哪些定时脚本能公开，哪些不能

审计对象：本机 4 套调度器上的全部任务与脚本（2026-10-21）。
判定只看三件事：**代码里有没有秘密 / 运行时会不会碰到个人数据 / 公开后会不会变成别人的违规工具。**

分级：

- **A 可直接共享** —— 无凭据、无个人数据、不操作第三方账号，改配置即可用。
- **B 需改造后共享** —— 代码本身没秘密，但硬编码了个人路径 / 私有服务 / 平台约定。
- **C 不可共享** —— 含凭据、个人身份、内部基础设施，或本身就在操作账号与身份。

## C · 不可共享（只给结论，不列清单）

有一部分任务不在这份文档里，也不打算列出来。它们不是「写得不好」，而是**碰的东西本身不该公开**：

- **登录态类**：脚本本身没有密码，但读写的是浏览器登录态。公开等于给出一套绕过平台风控的流程，
  同时把自己的账号摆到台面上。
- **个人身份类**：包含真实姓名、身份资料、沟通记录与业务数据。这是个人档案，不是技术资产。
- **凭据与备份类**：备份产物本身就是最高危资产（完整 profile、登录态快照）。备份脚本私有，
  备份目录永远在 `.gitignore` 里，且体积要有阈值告警。
- **内部设施类**：主机地址、SSH 私钥路径、内部接口。公开等于给出一张资产清单。

判断标准只有一句：**这段代码在操作什么？**
如果答案是「我的账号 / 我的身份 / 我的机器」，它就不进这个仓库，也不在这里点名。

## Agent 提示词也算「定时脚本」

59 个 Hermes 任务里有 12 个、DSH 还有 14 个不是脚本而是提示词。它们同样不能公开：
里面是真实姓名、账号、话术、阈值和每天的实际产出。**共享审核必须把提示词一并算进去**，
只审 `.sh`/`.py` 会漏掉一半风险。

## 数量对不上是正常的

`jobs.json` 里 59 条、launchd 28 条、noagent 11 条、schedule 14 条，加起来不等于任务数——
**同一个任务在不同调度器上有副本**（迁移期并行）。审计按「去重后的任务」计数，否则会重复评估。
这也解释了为什么启用数看着奇怪：停用不等于删除。
