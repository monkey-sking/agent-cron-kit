# maintenance：周期性清理

一周跑一次，处理四类东西：

| 段 | 处理什么 | 动作 |
|---|---|---|
| 1 | >30 天的轮转日志（`*.log.1`、`*.error.log.20260816`） | 删除 |
| 2 | >30 天的 `request_dump_*` 调试产物 | 删除 |
| 3 | 已删除任务的残留输出目录 | 删除 |
| 4 | 主文件 >30KB 的 skill | 只提醒（该拆 references） |
| 5 | 暂停 >30 天的任务 | 只提醒（停用不等于删除） |
| 6 | 单文件 >500M 的备份 / backups 总量 >5G | 只告警 |
| 7 | 数据目录总量 >10G | 只告警 |

**删除只发生在 1–3 段，且都是「可再生/已无主」的东西。4–7 段永远只是提醒。**

## 为什么备份体积要单独告警

真实事故：备份脚本漏排了一个 2.7G 的可再下载模型目录，每份备份包 2.4G，
保留 10 份 = 常驻 24G，数据目录一路涨到 29G。清理脚本救不了这个——
必须从源头修备份脚本。所以这里只做阈值告警，逼人去看。

## 用法

```bash
AGENT_HOME=~/.hermes bash maintenance_cleanup.sh --dry-run   # 先看会删什么
AGENT_HOME=~/.hermes bash maintenance_cleanup.sh
```

`AGENT_HOME` 默认 `~/.hermes`，指向你自己的数据目录即可复用。
输出约定：什么都没做 → 零输出。
